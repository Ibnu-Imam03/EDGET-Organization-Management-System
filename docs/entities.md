# EDGET Organization Management System — Database Entities

## 1. Overview

This document defines the initial set of entities for the EDGET Organization Management System. These entities represent the organization's members, leadership, educational activities, Ziyara visits, events, financial transactions, and documentation.

The entity list will serve as the foundation for developing the Entity-Relationship Diagram (ERD) and designing the SQL Server database.

## 2. Entity List

### Person and Organization Management
1. **Person** — Stores shared personal information.
2. **Member** — Stores information about organization members.
3. **Executive** — Stores leadership roles and sector responsibilities.
4. **Child** — Stores information about children participating in educational activities.
5. **Family** — Stores family and household information.
6. **Sector** — Represents the organization's operational sectors.

### Academic Management
7. **TeachingSession** — Represents a scheduled teaching activity.
8. **TeachingRecord** — Records teaching details and learning progress.

### Ziyara Management
9. **ZiyaraSession** — Represents a planned family visit or home-teaching activity.
10. **ZiyaraRecord** — Records visit details and outcomes.
11. **ZiyaraSessionMember** — Records which members participate in each Ziyara session and their attendance status.

### Event Management
12. **EventRecord** — Records organizational events, such as welcome programs, closing ceremonies, and trips.

### Finance Management
13. **FinanceTransaction** — Records organizational income and expenses.
14. **FinanceCategory** — Classifies financial transactions.
15. **FundraisingSale** — Records fundraising sales, including chocolate sales.

### Information and Reporting
16. **Document** — Stores references to organizational documents and information.
17. **Report** — Represents reports submitted by sectors or generated by the system.

## 3. Design Status

**Current status:** Initial entity identification.

The next design phase will define attributes, primary keys, foreign keys, relationships, and cardinalities. The resulting ERD will guide the implementation of the SQL Server database.

*Note: Entity names and attributes may be refined during the database design process.*
